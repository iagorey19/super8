## 2. PADRÕES DE CÓDIGO

### React 19 — Eventos de formulário
- **Obrigatório**: `e.currentTarget.value` em handlers onChange
- **Proibido**: `e.target.value` (tipagem incorreta no React 19)

### React Keys
- **Proibido**: índices numéricos simples (`i`, `idx`) em listas com reordenação ou filtragem
- **Obrigatório**: IDs únicos ou chaves compostas estáveis (`${id}-${index}`)

### TypeScript
- Tipos centralizados em `src/lib/types.ts`
- Ao alterar tipos, verificar TODOS os consumidores (componentes, hooks, seed)
- Evitar `any` — usar tipos específicos ou `unknown` + type guard

### Datas
- **Banco**: ISO strings (`"2026-06-21"` ou ISO completo com `T`)
- **UI**: `DD/MM/YYYY` via `formatDate()` em `src/lib/utils.ts`

### Moeda
- `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })`
- Sempre usar em todo o financeiro

### Mobile-First
- Todas as páginas responsivas: `flex-wrap`, `grid-cols-1 sm:grid-cols-*`, `hidden sm:block`
- Botões de ação principais visíveis sem scroll no mobile
- Tabelas: `overflow-x-auto` + `min-w-[650px]` para scroll horizontal
- Modais: centralizados, `overflow-y-auto`, padding lateral
- Touch targets ≥ 44px

## 3. REGRAS DE NEGÓCIO

### Escopo
- **Público**: Grupos de amigas que jogam padel semanalmente
- **Tone**: Mobile-first, brasileiro, confraternização > competição

### Whist (Americano)
- 8 atletas/grupo, 7 rodadas, 2 quadras/rodada
- Cada atleta dupla com todos exatamente uma vez
- Cada atleta enfrenta todos exatamente duas vezes

### Pontuação
- `max_score` configurável por torneio (default 5)
- Partida termina quando atleta atinge `max_score` games
- Tiebreak: se ambos em `max_score - 1`, vence por 2
- Ranking: Total games vencidos (desempate: confronto direto)
- Rankings anuais normalizam `total_games` proporcionalmente (`games * 5 / max_score`)
- Pontos finais: 1º=8pts, 2º=7pts … 8º=1pt

### Categorias
- **4e5**: Nível 4 e 5. Quadras A/B
- **6e7**: Nível 6 e 7. Quadras C/D
- Torneio pode ter 1 ou 2 categorias simultâneas
- Cada categoria tem grupo próprio de 8 atletas e ranking independente

### Perfis
- **Admin**: CRUD completo, aprovar/rejeitar, placar ao vivo, sorteios, financeiro, ranking anual
- **Atleta**: Ver jogos/ranking, histórico, auto-cadastro, editar perfil
- **Patrocinador**: Ver investimento, resultados, fotos, agradecimentos, editar perfil
- **Apoiador**: Contribui com brindes (kit para todos ou sorteio). Sem login — cadastrado pelo admin

## 4. SEGURANÇA

- **Senhas**: bcrypt (10 rounds) em `public.users`. Verificadas via `bcrypt.compare()` server-side
- **Token**: HMAC-SHA256 com `AUTH_TOKEN_SECRET`. Expira em 24h. Cookie httpOnly + sessionStorage (cache)
- **Rate Limiting**: Login (5/min), POST /api/data (30/min), admin-register (10/min), upload (30/min)
- **XSS**: URLs sanitizadas com `sanitizeUrl()` em inputs de patrocinadores e fotos
- **Open Redirect**: Parâmetros `next`/`redirect` validados com `isSafeRedirect()`
- **Security Headers**: `X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, `Referrer-Policy`
- **Zod Validation**: Payload de `POST /api/data` validado contra schema no servidor
- **NUNCA hardcodar** chaves, senhas, tokens. Usar `.env.local` + Vercel Env Vars.
- **Role filter**: GET /api/data oculta email/phone/avatar de não-admin

## 5. PERSISTÊNCIA

- `upsert` com `onConflict: "id"` (cria ou atualiza)
- IDs seed são strings textuais (`"admin-001"`) — compatível com TEXT PRIMARY KEY
- Runtime: `crypto.randomUUID()` para novos registros
